# Lab Notes: Building the Celeb Book App with Jetpack Compose

## Learning Outcomes

By completing this lab, you will be able to:

- Create Kotlin data classes.
- Manage UI-related data using a `ViewModel`.
- Build screens with Jetpack Compose.
- Navigate between screens using Navigation Compose.
- Pass an argument from one screen to another.
- Update data and return to the previous screen.
- Diagnose common Android Studio build and runtime problems.

---

## Overview

In this lab, you will build **Celeb Book**, a simple multi-screen Android application that allows users to:

1. View a list of celebrities.
2. Open a celebrity's details.
3. Edit the celebrity's name and biography.
4. Save the changes and return to the list.

The app uses sample data stored in memory. It does **not** use a database, so changes are not guaranteed to survive when the app process is destroyed.

## Architecture

```text
Contact data model
        ↓
ContactViewModel (holds and updates the list)
        ↓
Compose screens (display and edit data)
        ↕
Navigation Compose (moves between screens)
```

- **Model:** `Contact.kt` describes one celebrity.
- **ViewModel:** `ContactViewModel.kt` holds the sample list and updates contacts.
- **UI:** Composable functions display the list and edit form.
- **Navigation:** `NavHost` defines destinations, and `NavController` navigates between them.

# Activity 2: Create the ViewModel

## Create `ContactViewModel.kt`

Create this file in the `com.example.celebbook` package using the same way above. 

Add:

```kotlin
package com.example.celebbook

import androidx.compose.runtime.mutableStateListOf
import androidx.lifecycle.ViewModel

class ContactViewModel : ViewModel() {

    private val _contacts = mutableStateListOf(
        Contact(
            1,
            "Taylor Swift",
            "Grammy-winning singer-songwriter."
        ),
        Contact(
            2,
            "Keanu Reeves",
            "Renowned actor known for action cinema."
        )
    )

    val contacts: List<Contact>
        get() = _contacts

    fun getContactById(id: Int): Contact? {
        return _contacts.find { it.id == id }
    }

    fun updateContact(updatedContact: Contact) {
        val index = _contacts.indexOfFirst {
            it.id == updatedContact.id
        }

        if (index != -1) {
            _contacts[index] = updatedContact
        }
    }
}
```

### What does the ViewModel do?

The ViewModel holds the list and provides functions to find and update a celebrity. The UI calls these functions instead of managing the list itself.

`mutableStateListOf` creates a Compose-observable list. When an item is replaced, Compose can recompose the UI that reads the list and show the updated data.

This example stores data **in memory only**. It does not save information to a database or permanent file.

# Activity 3: Build the UI

## Step 1: Create `ui/ContactItem.kt`

This composable displays one celebrity as a clickable card.

```kotlin
package com.example.celebbook.ui

import androidx.compose.foundation.clickable
import androidx.compose.foundation.layout.fillMaxWidth
import androidx.compose.foundation.layout.padding
import androidx.compose.material3.Card
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import androidx.compose.ui.unit.dp
import com.example.celebbook.Contact

@Composable
fun ContactItem(
    contact: Contact,
    onClick: () -> Unit
) {
    Card(
        modifier = Modifier
            .fillMaxWidth()
            .padding(8.dp)
            .clickable { onClick() }
    ) {
        Text(
            text = contact.name,
            modifier = Modifier.padding(16.dp)
        )
    }
}
```

The `onClick` callback lets the parent screen decide what happens when the user taps a card. The item itself does not need to know about navigation.

## Step 2: Create `ui/ContactListScreen.kt`

This screen displays all celebrities in a scrollable list.

```kotlin
package com.example.celebbook.ui

import androidx.compose.foundation.layout.fillMaxSize
import androidx.compose.foundation.lazy.LazyColumn
import androidx.compose.foundation.lazy.items
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import com.example.celebbook.Contact

@Composable
fun ContactListScreen(
    contacts: List<Contact>,
    onContactClick: (Int) -> Unit
) {
    LazyColumn(
        modifier = Modifier.fillMaxSize()
    ) {
        items(
            items = contacts,
            key = { contact -> contact.id }
        ) { contact ->
            ContactItem(
                contact = contact,
                onClick = {
                    onContactClick(contact.id)
                }
            )
        }
    }
}
```

### Why use `LazyColumn`?

`LazyColumn` creates list items as they are needed for display and supports vertical scrolling. The `key` gives each item a stable identity.

The callback `onContactClick` receives the selected contact's ID. The navigation code will use that ID to open the correct celebrity.

## Step 3: Create `ui/EditContactScreen.kt`

This screen lets the user change a celebrity's name and biography.

```kotlin
package com.example.celebbook.ui

import androidx.compose.foundation.layout.Arrangement
import androidx.compose.foundation.layout.Column
import androidx.compose.foundation.layout.fillMaxWidth
import androidx.compose.foundation.layout.padding
import androidx.compose.material3.Button
import androidx.compose.material3.OutlinedTextField
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue
import androidx.compose.ui.Modifier
import androidx.compose.ui.unit.dp
import com.example.celebbook.Contact

@Composable
fun EditContactScreen(
    contact: Contact,
    onSaveContact: (Contact) -> Unit
) {
    var name by remember(contact.id) {
        mutableStateOf(contact.name)
    }

    var bio by remember(contact.id) {
        mutableStateOf(contact.bio)
    }

    Column(
        modifier = Modifier
            .fillMaxWidth()
            .padding(16.dp),
        verticalArrangement = Arrangement.spacedBy(12.dp)
    ) {
        Text(text = "Edit Celebrity")

        OutlinedTextField(
            value = name,
            onValueChange = { name = it },
            label = { Text("Name") },
            modifier = Modifier.fillMaxWidth()
        )

        OutlinedTextField(
            value = bio,
            onValueChange = { bio = it },
            label = { Text("Biography") },
            modifier = Modifier.fillMaxWidth()
        )

        Button(
            onClick = {
                onSaveContact(
                    contact.copy(
                        name = name,
                        bio = bio
                    )
                )
            },
            modifier = Modifier.fillMaxWidth()
        ) {
            Text("Save Changes")
        }
    }
}
```

### Understand the edit form

- `remember` holds the text-field state while the user edits.
- `remember(contact.id)` initializes the fields for the selected celebrity ID.
- `contact.copy(...)` creates an updated `Contact` object while preserving the ID.
- `onSaveContact` passes the updated object to the caller. The navigation layer will connect this callback to the ViewModel and return to the list.

# Activity 4: Understand and Implement Navigation

## What is a route?

A **route is a name or pattern that identifies a destination in an app's navigation graph**. It tells the navigation system which screen the app should display.

Think of routes as room names in a building: the name tells you where to go.

This lab has two destinations:

| Route | Purpose |
|---|---|
| `contact_list` | Displays the list of celebrities. |
| `edit_contact/{contactId}` | Displays the edit screen for the celebrity whose ID is supplied. |

### Fixed route versus route with an argument

A fixed route is simply a destination name:

```kotlin
"contact_list"
```

The edit route contains an argument in braces:

```kotlin
"edit_contact/{contactId}"
```

`{contactId}` is a placeholder. When navigating, the app supplies a real value:

```kotlin
navController.navigate("edit_contact/1")
```

Here, `1` is the ID of Taylor Swift in the sample data. For Keanu Reeves, the app navigates to:

```kotlin
navController.navigate("edit_contact/2")
```

The argument lets the edit screen identify which celebrity to load.

## Four navigation terms

- **Route:** Identifies a destination and, if needed, its arguments.
- **Destination:** The screen or location the user navigates to.
- **`NavHost`:** Defines the navigation graph and displays the current destination.
- **`NavController`:** Navigates between destinations and manages the back stack.

The **back stack** is the navigation history. When the user opens the edit screen from the list, the list remains underneath it. Calling `popBackStack()` returns to the previous destination.

## Step 1: Replace `MainActivity.kt`

Replace the contents of `MainActivity.kt` with:

```kotlin
package com.example.celebbook

import android.os.Bundle
import androidx.activity.ComponentActivity
import androidx.activity.compose.setContent
import androidx.compose.foundation.layout.fillMaxSize
import androidx.compose.material3.MaterialTheme
import androidx.compose.material3.Surface
import androidx.compose.runtime.key
import androidx.compose.ui.Modifier
import androidx.lifecycle.viewmodel.compose.viewModel
import androidx.navigation.NavType
import androidx.navigation.compose.NavHost
import androidx.navigation.compose.composable
import androidx.navigation.compose.rememberNavController
import androidx.navigation.navArgument
import com.example.celebbook.ui.ContactListScreen
import com.example.celebbook.ui.EditContactScreen

class MainActivity : ComponentActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        setContent {
            MaterialTheme {
                Surface(
                    modifier = Modifier.fillMaxSize()
                ) {
                    val navController = rememberNavController()
                    val contactViewModel: ContactViewModel = viewModel()

                    NavHost(
                        navController = navController,
                        startDestination = "contact_list"
                    ) {
                        // Destination 1: Celebrity list
                        composable("contact_list") {
                            ContactListScreen(
                                contacts = contactViewModel.contacts,
                                onContactClick = { contactId ->
                                    navController.navigate(
                                        "edit_contact/$contactId"
                                    )
                                }
                            )
                        }

                        // Destination 2: Edit a selected celebrity
                        composable(
                            route = "edit_contact/{contactId}",
                            arguments = listOf(
                                navArgument("contactId") {
                                    type = NavType.IntType
                                }
                            )
                        ) { backStackEntry ->

                            val contactId = backStackEntry
                                .arguments
                                ?.getInt("contactId")

                            val contact = contactId?.let {
                                contactViewModel.getContactById(it)
                            }

                            if (contact != null) {
                                key(contact.id) {
                                    EditContactScreen(
                                        contact = contact,
                                        onSaveContact = { updatedContact ->
                                            contactViewModel.updateContact(
                                                updatedContact
                                            )

                                            navController.popBackStack()
                                        }
                                    )
                                }
                            }
                        }
                    }
                }
            }
        }
    }
}
```

## Step 2: Follow the navigation flow

1. `rememberNavController()` creates the navigation controller.
2. `viewModel()` obtains the `ContactViewModel`.
3. `NavHost` registers both routes and sets `contact_list` as the starting destination.
4. When the user taps a celebrity, the list screen calls `onContactClick` with that celebrity's ID.
5. `navController.navigate("edit_contact/$contactId")` opens the edit destination and passes the ID.
6. The destination reads the argument and looks up the corresponding contact in the ViewModel.
7. When the user taps **Save Changes**, the callback updates the ViewModel and then calls `popBackStack()`.
8. The list screen appears again and displays the updated information.

The `key(contact.id)` call associates the edit form's remembered state with the selected celebrity.
